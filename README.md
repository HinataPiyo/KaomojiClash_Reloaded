# KaomojiClash_Reloaded

顔文字を操作して敵にぶつけ、ウェーブを突破しながら成長する、制作途中の2D物理アクションゲームです。プレイヤーはマウスで顔文字を引っ張って飛ばし、敵より速い衝突を狙います。敵を倒して経験値を得ると、ウェーブの合間にアリーナオブジェクトを選択・強化できます。

> **開発状況:** 制作途中のプロジェクトです。このREADMEはリポジトリ内の設定・シーン・ソース・データを確認してまとめたもので、Unity Editor上でのプレイ確認やビルド確認は行っていません。

## ゲームの特徴

- **顔文字を組み立てる:** 輪郭の括弧と、目・口・左右の手に割り当てられた記号を組み合わせて表示します。記号の候補や各パーツのデータは `ScriptableObject` で管理されています。
- **引っ張って飛ばす戦闘:** ドラッグした方向と反対向きにプレイヤーを発射します。敵との衝突では速度を比べ、一定の条件を満たすとダメージが発生します。
- **ウェーブごとのアリーナ戦:** 次の敵との遭遇位置へプレイヤーが移動し、その位置に壁で区切られた戦闘エリアを用意します。敵を全滅させるか制限時間を迎えると、ウェーブ進行または結果表示へ移ります。
- **撃破と装置の成長:** 敵の撃破で経験値を獲得し、レベルアップ時にはアリーナオブジェクトを選択できます。現在データとして確認できるオブジェクトは、衝突で反発力を与える「Bumper」です。

## 操作方法

| 操作 | 入力 | 動作 |
| --- | --- | --- |
| プレイヤーを発射 | マウス左ボタンを押したままドラッグし、離す | ドラッグ方向と反対向きに発射。ドラッグ距離に応じて力が変わり、上限距離が設定されています。 |
| 敵を攻撃 | 発射後、敵に衝突 | 独立した攻撃ボタンはありません。プレイヤーが敵より十分速い場合にダメージを与えます。 |
| メニュー操作 | 画面上のUIボタンをクリック | 顔文字パーツの選択、スキル設定、シーン移動などを行います。 |

ゲームプレイ用の入力アクションは `Press` と `Point` で、入力アセットにはマウスの左ボタンとポインター位置が割り当てられています。キーボードによる移動・攻撃操作は、確認した実装では見つかりませんでした。

## ゲームシステム

### 顔文字キャラクター

[`KaomojiData`](Assets/Scripts/Kaomoji/KaomojiData.cs) は口・左右の目・左右の手に対応する [`SymbolData`](Assets/Scripts/Kaomoji/SymbolData.cs) を持ちます。[`KaomojiSetUp`](Assets/Scripts/Kaomoji/KaomojiSetUp.cs) が各記号をつなぎ、左右の括弧を加えてTextMeshProで表示します。企画で挙げられている `()`、`^^`、`ω` は固定の描画パーツではなく、データから選ばれる記号の例です。

現在のプレイヤー用データ [`KaomojiData_Player`](Assets/Datas/KaomojiData_Player.asset) に設定されているのは口の記号のみで、目と手は未設定です。Resources内には目と口の記号データがありますが、手の記号データは確認できませんでした。

### ステータスとコンボ

手の記号データには `Stamina`、`Speed`、`Power`、`Guard` があり、共通の [`StatsCalculator`](Assets/Scripts/Kaomoji/StatCalculator/StatsCalculator.cs) を継承したプレイヤー・敵の計算クラスが基礎値と記号の値から数値を算出します。プレイヤー側では、スタミナが体力、スピードが発射力、パワーが与えるダメージに使われています。ダメージを与えるとコンボが増え、[`Combo`](Assets/Scripts/Player/Combo.cs) が返すダメージ倍率がパワー計算に反映されます。

目の記号データには `CriticalDamage` と `CriticalRate` の項目があり、ホーム画面のステータス表示にも含まれます。ただし、確認した衝突ダメージ処理ではクリティカル値や `Guard` をダメージ計算に適用していません。ステータス表示・計算用データの存在と、戦闘効果の実装は区別してください。

### 戦闘と敵

- プレイヤーはドラッグした距離と `Speed` を使って発射力を計算します。ドラッグ距離は設定値で制限されます（[`Movement`](Assets/Scripts/Player/Movement.cs)、[`PlayerStatsCalculator`](Assets/Scripts/Kaomoji/StatCalculator/PlayerStatsCalculator.cs)）。
- プレイヤーと敵は2D物理衝突で反射します。敵へのダメージは衝突速度が所定の条件を満たした場合に発生し、ダメージ量はパワーをもとに計算します。
- 敵は一定時間待機した後、プレイヤーの方向を向いて発射する動作を繰り返します。待機時間には個体ごとのランダムな変化が加わります。
- ウェーブ開始時は敵との遭遇位置へプレイヤーを移動させ、壁で囲まれたエリア内に追加の敵を出現させます。ウェーブ数に応じた敵数計算や、10ウェーブごとの構成段階変更が実装されています。
- 戦闘中には制限時間があり、敵の全滅または時間切れでウェーブ状態が切り替わります。プレイヤーの体力が尽きた場合も失敗結果へ進みます。

### 経験値とアリーナオブジェクト

敵撃破時に経験値がウェーブ単位で蓄積され、ウェーブ終了時にプレイヤーへ加算されます。レベルアップに応じてオブジェクト選択画面を表示し、選んだオブジェクトを戦闘エリアに生成します。所持済みオブジェクトを再選択するとレベルを上げる仕組みもあります（[`ArenaObjectController`](Assets/Scripts/ArenaObject/ArenaObjectController.cs)）。

確認できたオブジェクトデータはBumperです。Bumperは衝突したキャラクターに反発力を加え、レベルに応じて反発力が変わります。企画にある広いマップを自由に移動する探索や、味方との遭遇は、確認したシーン・コードからは実装を確認できませんでした。

### スキル

スキルは [`SkillData`](Assets/Scripts/Skill/SkillData.cs) を基底とする `ScriptableObject` で、名前・コスト・説明を持ちます。確認できたスキルデータは、壁での反射力を扱う [`WallReflection`](Assets/Scripts/Skill/WallReflection.cs) です。ホーム画面にはスキル一覧・説明・スロット設定UIがあり、最大5スロットとスキルコストに応じた連続スロットの使用処理があります（[`SkillSlotsController`](Assets/Scripts/UI/Home/SkillSetting/SkillSlotsController.cs)）。

ただし、現在のスキル機能は開発途中です。重複スキルの装備を防ぐ処理は確認できず、スロットに保存した装備構成と、戦闘中のスキル取得処理は分離しています。戦闘中に参照する `TryGetSkill` は装備スロットではなく [`GlobalVariables.HasSkills`](Assets/Scripts/Core/GlobalVariables.cs) を検索し、ホーム画面ではテスト用の `WallReflection` をその一覧に加えています。そのため、「コスト合計5以内・同じスキルを重複装備しない」という企画上のルールが一通り動作する完成済みビルド機能としては記載していません。

## 技術的な工夫

- **データと表示・処理の分離:** 顔文字の組み立て情報、記号のステータス、プレイヤー・敵の基礎値、ウェーブ設定、スキル、アリーナオブジェクトを用途ごとの `ScriptableObject` に分けています。記号とアリーナオブジェクトのデータは `Resources` から読み込みます。
- **共通ステータス計算と役割別処理:** 抽象クラス `StatsCalculator` に共通の計算窓口を定義し、プレイヤー用と敵用の計算クラスがそれぞれの基礎値や挙動を実装します。`IAttackable` や `IWave` などのインターフェースを通じて、衝突・ウェーブ進行側から具体クラスへの依存を抑えています。
- **ウェーブ状態の明示:** [`WaveController`](Assets/Scripts/Wave/WaveController.cs) は待機、戦闘、レベルアップ時の選択、成功・失敗、時間切れを状態として扱い、敵生成・UI・カメラ・シーン管理と連携します。
- **データ駆動の追加ポイント:** 新しいスキルは `SkillData` の派生データ型として定義でき、アリーナオブジェクトも `ArenaObjectData` と対応するロジックを組み合わせます。ただし、スキルについては上記のとおり装備構成と戦闘時の参照がまだ一貫していません。

## 実行方法

1. Unity Hubでこのリポジトリのルートフォルダーをプロジェクトとして追加します。
2. [`ProjectSettings/ProjectVersion.txt`](ProjectSettings/ProjectVersion.txt) に記録された **Unity 6000.3.20f1** を使用して開きます。
3. [`TitleScene.unity`](Assets/Scenes/TitleScene.unity) を開いてPlayを開始します。ビルド設定では `TitleScene`、`HomeScene`、`BattleScene` の順に登録されています。タイトルシーンではデータ読み込み後にホームシーンへ遷移する処理があります。

必要なプラットフォーム、実機要件、配布ビルド手順はリポジトリ内で確認できなかったため、ここでは指定していません。
